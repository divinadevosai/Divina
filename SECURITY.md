# Security model

Divina runs a small web server on your computer. It is built so that only
**you, in the Divina page, on this computer** can use it.

1. **Local only.** The server listens on `127.0.0.1`, so other devices — on
   your Wi-Fi, at a café — cannot connect at all.
2. **Other websites are refused.** Any page open in your browser could try
   to send requests to Divina's port. `src/middleware.ts` rejects every
   `/api` request whose `Sec-Fetch-Site` or `Origin` shows it came from
   another site, any POST that doesn't say where it came from, and any
   request whose `Host` is not a loopback name (this defeats DNS rebinding).
   No other site may put Divina in a frame (`X-Frame-Options: DENY`,
   `frame-ancestors 'none'`), so it can't trick you into clicking *Allow*.
3. **Changing things needs more.** Settings and desktop control also require
   a custom header, which a cross-site page cannot send without a CORS
   preflight that the server never approves.
4. **Keys stay on the server, encrypted.** Every saved secret (AI, voice,
   email, calendar and other keys) is sealed with AES-256-GCM before it is
   written to `settings.local.json`; the setting's name is bound in, so a
   sealed value can't be swapped or altered unnoticed. The 256-bit key is
   in `vault.key`, locked with Windows DPAPI to your Windows account (with
   Divina's own entropy), or on a Mac kept in your login Keychain (handed to
   `security` on its input, never its command line), so a copied file,
   backup or disk read on another computer or account is useless
   (`src/lib/server/vault.ts`). Keys saved in the
   clear by older versions are sealed the first time they're read. API keys
   are read only by server code, sent to their own company in a header
   (never in a URL), and never sent to the page or logged. Any saved secret that turns up in an upstream error is replaced
   with "…" before the message leaves the server. Settings are write-only
   for secrets, and every setting is checked against the shape it must have
   (model names, leagues and the calendar address end up in URLs).
5. **Only Divina's own scripts run in the page.** A Content-Security-Policy
   limits scripts to Divina itself — no CDN or third-party code, the hand
   tracking engine and model included — and
   links from data — news, Instagram, projects, the AI — only open if they
   are plain `http(s)` addresses, so a `javascript:` link can't run code.
6. **Spending guard.** AI and voice requests are capped per minute and per
   day (`src/lib/server/ratelimit.ts`; raise with `DIVINA_AI_DAILY_LIMIT`,
   `DIVINA_TTS_DAILY_LIMIT`), and each AI request is checked and capped in
   size (24 turns, 4,000 characters each) whatever the page sends.
7. **The AI can't be tricked into using your computer.** Headlines, captions
   and calendar titles are marked as untrusted data in the AI's instructions.
   Actions the *AI* starts on your computer are limited: music and volume go
   ahead, anything that could leak or change something asks you first, and
   reading your clipboard or screen is never done on its own initiative.
   Commands you speak yourself are not affected.
8. **Desktop control** is off unless `DIVINA_DESKTOP_BRIDGE=1` is set in
   `.env.local` (it cannot be switched on from the page; the Windows
   installer turns it on). Verbs are a closed
   list, programs start without a shell, scripts are constants and your
   words only ever travel as data. There is no shutdown, restart, delete or
   force-quit.

## Browser edition

- A static site with no server; the visitor's settings and own keys stay in
  their browser and each key goes only to its own company.
- Keys are stored only sealed (AES-256-GCM) in localStorage. The key that
  seals them is generated by the browser as non-extractable and kept in
  IndexedDB: no script, Divina's included, can read its bytes, so a copy of
  the browser's storage files is useless (`src/web/vault.ts`). Opened keys
  live only in the tab's memory.
- Its policy allows only the exact inline scripts it ships (by SHA-256
  hash), no `eval`, no outside images or scripts, and network access only
  to the AI and voice companies (Google, Anthropic, OpenAI, ElevenLabs), MET
  Norway, OpenStreetMap, Hacker News and CoinGecko — so even a successful
  injection could not send a key anywhere else.
- Tested: poisoned headlines, links and calendar events don't run; attempts
  to send data out by fetch, image or script are blocked.

## Windows installer

- Installs for your user only; the build refuses to package any `.env`
  file, saved settings, personal data file or saved key.
- The web installer downloads Node.js over HTTPS from nodejs.org and checks
  its SHA-256 against the value fixed at build time before using it.
- Stopping Divina (on update or uninstall) only stops processes after
  confirming Divina is really the one answering, so a stale record can't
  close an unrelated program.
- The uninstaller deletes only Divina's own files, never "everything in its
  folder", and asks before deleting your settings.

## What encryption can't do

Nothing on a computer is perfectly safe. Encryption protects keys from a
copied file, a backup, a lost disk or another account. It can't protect them
from malware already running as you, or from someone using your unlocked
account or browser profile — they could use Divina (or ask Windows) just as
you can. Keep your PC locked and up to date, and use spending limits on your
API accounts.

## If a key leaks

Revoke it on its company's site — Google (aistudio.google.com/apikey),
Anthropic (platform.claude.com → API keys), OpenAI
(platform.openai.com/api-keys) or ElevenLabs (elevenlabs.io → Developers →
API keys) — create a new one, and paste it into Settings. Nothing else needs
changing.

## Licence keys (Windows and Mac)

Off in the normal free build. A build made for sale (`DIVINA_REQUIRE_LICENCE=1`)
checks its licence with Lemon Squeezy's public License API
(`src/lib/server/licence.ts`). That API needs no secret of ours, so the app
carries nothing that could open the shop. Only the buyer's key and a random
device name are sent; the reply must name Divina's store and product, so a
key from another shop is refused and its seat given straight back. The key
is sealed in the vault, never sent back to the page, and the route answers
only Divina's own page. Divina runs on the buyer's computer, so the check can
be edited out by someone determined: it keeps honest people honest; it is
not DRM.
